# happy-server-self-host

Self-host runtime for [Happy](https://happy.engineering) — the sync server
for the native iOS and Android clients, packaged for `happy server`.

## Usage

```bash
npm install -g happy happy-server-self-host
happy server
```

`happy server` (from the `happy` CLI) discovers this package automatically and
runs it with embedded PGlite storage and local filesystem uploads — no Postgres,
no Redis, no S3. It writes `settings.serverUrl` so the daemon and CLI target
your local server.

The bundled `happy-server` binary can also be run directly:

```bash
happy-server migrate   # apply database migrations
happy-server serve     # start the server
```

## What this package is

This is the *publishing shell* around `packages/happy-server`, which is private
and is what the hosted Happy backend deploys. The server source lives there; this
package bundles its `sources/standalone.ts` entrypoint into `dist/standalone.mjs`
and ships the Prisma schema and migrations alongside it.

Build artifacts (`dist/`, `prisma/`) are generated by
`scripts/build-runtime.cjs`; they are not checked in.

The build also includes the repository's PGlite Bytes compatibility patch. The package's `postinstall` applies it to the resolved adapter and generates the Prisma client, including when npm hoists dependencies. Run installation scripts when installing this package.

For package validation, install the tarball outside the monorepo, then run `node packages/happy-server-self-host/scripts/test-pglite-bytes.cjs /absolute/consumer/node_modules/happy-server-self-host` from the source checkout. This reads machine key records through Prisma with both CommonJS and ESM adapters; a workspace-only test can inherit the root postinstall patch and miss packaging failures. The Server CI workflow runs this isolated install check.

## Personal macOS relay

The optional `scripts/macos-service.py` installs a server-only LaunchAgent. Public HTTPS ingress has a separate lifecycle; stopping this server does not stop that ingress. Use a pinned package directory, Node.js and Python 3. Keep the private configuration outside Git with mode 0600:

```json
{
  "node": "/opt/homebrew/bin/node",
  "package": "/absolute/release/node_modules/happy-server-self-host",
  "environment": {
    "NODE_ENV": "production",
    "DB_PROVIDER": "pglite",
    "HOST": "127.0.0.1",
    "PORT": "3005",
    "PUBLIC_URL": "https://happy.example.com",
    "DATA_DIR": "/absolute/private/data",
    "PGLITE_DIR": "/absolute/private/data/pglite",
    "HANDY_MASTER_SECRET": "GENERATE_A_PRIVATE_RANDOM_SECRET",
    "HAPPY_ALLOWED_PUBLIC_KEYS": "64_HEX_ED25519_ACCOUNT_PUBLIC_KEY"
  }
}
```

Run database migrations with the same environment before starting. `HAPPY_ALLOWED_PUBLIC_KEYS` restricts signature-verified account authentication; comma-separated keys are accepted. Explicit empty or malformed values reject startup. An unset variable preserves upstream open registration. Changing the allowlist does not revoke previously issued tokens. The signing public key is not the content-encryption key. Never put an account recovery secret on the server.

```sh
python3 /absolute/package/scripts/macos-service.py install --config /absolute/private/service.json
python3 /absolute/package/scripts/macos-service.py start
python3 /absolute/package/scripts/macos-service.py status
python3 /absolute/package/scripts/macos-service.py stop
python3 /absolute/package/scripts/macos-service.py uninstall
```

Install does not start the service. The source path owns `local.happy-personal-relay.server`; a different source must first use the old owner's stop/uninstall. Database and account data survive uninstall. Runtime and logs live in `~/.local/share/happy-personal-relay`; logs rotate at 5MB with two backups. Status reports process registration, not phone readiness. Maintain a consistent backup of the database, uploads and server master secret before replacing the package.

Server changes require a new Happy account/profile for this deployment; preserve the previous account and home rather than reusing its token. HTTPS, Socket.IO and encrypted-message round trips must be checked through the public URL before phone acceptance. This personal service does not configure APNs or remove iOS signing requirements.
